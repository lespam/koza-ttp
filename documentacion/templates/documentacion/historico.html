{% translate "El problema" %}

{% blocktranslate trimmed %}La MLB programa 2,430 juegos para 30 equipos en unos 180 días. Cada equipo viaja entre ciudades, y la distancia cambia mucho de un equipo a otro. En 2016, Seattle viajó 76,683 km y los Cubs de Chicago viajaron 39,015 km.{% endblocktranslate %}

{% blocktranslate trimmed %}Encontrar el calendario con la menor distancia total se conoce como el Problema de Transportación de Torneo (PTT). Es un problema NP-duro: el número de calendarios posibles crece tan rápido que no se pueden revisar todos.{% endblocktranslate %}

{% translate "El método" %}

{% blocktranslate trimmed %}La programación genética (PG), propuesta por John Koza en 1992, imita la evolución. Crea una población de soluciones, se queda con las mejores y las combina y modifica para formar una nueva generación.{% endblocktranslate %}

  1. {% blocktranslate trimmed %}Representación: cada calendario es un árbol. Sus nodos son operaciones como crear_juego (fecha, equipo local, equipo visitante) y obtener_calendario, que une dos listas de juegos.{% endblocktranslate %}
  2. {% blocktranslate trimmed %}Viabilidad (C1): cada equipo debe jugar exactamente el número de juegos que pide el torneo. Un valor de 0 significa que el calendario es válido.{% endblocktranslate %}
  3. {% blocktranslate trimmed %}Distancia (C2): la suma de los traslados, calculada con la fórmula de haversine sobre las coordenadas de cada estadio.{% endblocktranslate %}
  4. {% blocktranslate trimmed %}Software: tres módulos (planificador, calculadora y programa genético) con la biblioteca DEAP, separados de una aplicación web en Django.{% endblocktranslate %}

{% translate "El hallazgo principal" %}

{% blocktranslate trimmed %}La programación genética no superó a la búsqueda aleatoria. Dio una distancia 19.5% mayor y tardó casi 17 veces más. El mejor calendario siempre salió de la generación inicial, que es aleatoria.{% endblocktranslate %}

{% translate "La tesis identificó estas causas:" %}

  • {% blocktranslate trimmed %}Los operadores genéricos de cruce y mutación cambian nodos sin conocer el problema. Casi siempre producen calendarios inválidos.{% endblocktranslate %}
  • {% blocktranslate trimmed %}La función de aptitud le da mucho más peso a la viabilidad que a la distancia. Un hijo inválido pierde siempre contra un padre válido.{% endblocktranslate %}
  • {% blocktranslate trimmed %}El algoritmo convergió pronto en un óptimo local y conservó solo las soluciones iniciales.{% endblocktranslate %}

{% blocktranslate trimmed %}Un resultado negativo también es un resultado. Muestra que la representación y los operadores importan tanto como el algoritmo.{% endblocktranslate %}

{% translate "Trabajo futuro" %}

{% blocktranslate trimmed %}La tesis propuso operadores contextuales: en lugar de cambiar nodos al azar, intercambiar series o bloques completos que mantengan el calendario válido. También mencionó la computación cuántica para explorar muchas configuraciones a la vez.{% endblocktranslate %}
